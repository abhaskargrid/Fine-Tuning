Project Report: Test-Case Level Attribution and Error Debugging
1. Objective and Problem Statement
In traditional Reinforcement Learning (RL) for code generation, models typically receive "sparse rewards" (e.g., 1 if all tests pass, -0.25 if any test fails). This black-box approach hinders model interpretability and creates steep learning curves, as the model receives no partial credit for near-correct logic and provides no telemetry on why it failed.
The objective of this analysis is to implement a Deep RL Interpretability Engine to open this black box. By integrating binary search test isolation, granular reward shaping, policy gradient token attribution, and automated curriculum generation, this study aims to provide complete transparency into model failures and generate highly targeted datasets to guide future RL policy optimization.
2. Methodology & Implementation
To evaluate the fine-tuned Qwen2.5-Coder-1.5B model effectively, the evaluation pipeline was completely restructured to calculate granular metrics and trace neural network gradients:
Binary Search Test Isolation: Because hidden test cases are bundled into a single block, an O(log N) binary search algorithm was implemented. When an execution crash occurs, the system recursively splits the array of assert statements in half and evaluates each batch, instantly isolating the exact edge case responsible for the failure.
Granular Reward Computation: To smooth the RL learning gradient, a custom mathematical reward function was applied. The engine evaluates isolated test cases, awarding the model +1.0 for every passing assertion and penalizing it -0.25 for every failed assertion.
Gradient-Based Attribution: To achieve true interpretability, the system utilizes a real PyTorch backward pass. A simulated policy gradient loss is calculated and scaled by the granular reward. By triggering loss.backward(), the system extracts the L2 norms of the token embedding gradients to identify the exact hallucinated tokens with the highest mathematical influence over the failure.

4. Automated Curriculum Generation
Using the granular reward computations, the system dynamically evaluated 15 unseen problems (HumanEval/50 through HumanEval/64) to construct an automated RL training curriculum. Rather than relying on static, human-assigned difficulty labels, the system ranks difficulty mathematically based on the model's zero-shot performance capabilities:

Curriculum Analysis:
🟢 EASY (Score = 100%): Problems like HumanEval/52 and HumanEval/60. The model passed these tests with high confidence. These are structured to be fed to the RL policy first to establish a baseline policy.
🟡 MEDIUM (Score 0% to 99%): Problems like HumanEval/53 (79.2%) and HumanEval/64 (37.5%). The model understands the core premise but fails specific edge cases. These provide the highest RL fine-tuning value.
🔴 HARD (Score < 0%): Problems like HumanEval/50, 51, and 63 (-25.0%). The model completely failed the logic. These are delayed until the end of training to prevent catastrophic forgetting.
5. Adversarial Test Bank Construction
To facilitate targeted data augmentation, the engine automatically extracts the exact edge cases that triggered the $-0.25$ penalties and deposits them into an Adversarial Test Bank (visible at the bottom of Screenshot 2).
As shown in the extracted telemetry, the system successfully identified consistent failure patterns. For example, in HumanEval/51, the model consistently failed on empty string inputs (assert candidate('') == '') and repetitive character strings (assert candidate('eeeee') == ''). Extracting these patterns enables highly targeted data augmentation for future training cycles.
6. Final Benefit & Conclusion
This attribution pipeline provides unprecedented transparency into RL failures. By replacing sparse pass/fail flags with granular rewards, real token-level gradient attribution, and dynamic curriculum sorting, the system enables highly targeted debugging. The extracted adversarial test bank directly informs the next cycle of data augmentation, ensuring the model's training is concentrated exactly on the edge cases and logical paradigms it currently misunderstands.
